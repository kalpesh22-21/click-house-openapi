**Audience:** remote developer extending question coverage and case-handling on the `data-agent-runtime` assistant.
This brief is data-first: every pattern below is grounded in captured traffic, with verbatim user text,
the SQL the system actually generated, and what worked vs. failed.

|---|---|---|---|---|---|

| `39638ce9…` (2026-10-12T19:26Z) | `b631c17c…` | `how many hours did ycFTPg nh, xoQijba rzPeO worked in last 3 months?` | `sql-3bb96dbe7e` | `PARSE_FAILED_CLOSED` | 4 (`hello`, `total employee count`, `highest pay`, named-person hours) |

Because a trace carries its **entire conversation history**, every prior question in the session is marked
`denied` when the latest turn is denied. Read "15 questions hit denials" as "**2 denial turns touching
15 question rows**". The remaining 103 of 116 SQL-level denials occur in harness sessions with no question
text (`sess-eval`, `sess-span-qa`) — see §4.2.

## 3. Pattern Catalog (per bucket)

Buckets are keyword-matched and **multi-label**: a question counts in every bucket it matches, so bucket
occurrence sums exceed 664. Per bucket below: occurrence/unique counts, every verbatim question, the SQL
families it maps to, and outcome notes. Question text longer than ~240 chars is shown verbatim-but-truncated
⏎ marks original newlines; full untruncated text is in Appendix A.

**How to read the SQL linkage.** SQL ids are linked at trace grain. Battery questions co-occur in one session,
so they share the battery's full working SQL set — the phase-1 ids (`Q1–Q108`, legend in
`phoenix_extract/summary.md`) are the question-specific canonical forms; `NEW` ids are first-seen in this
window. Full SQL texts are deliberately not duplicated here: see `queries_all.json` (Appendix B maps ids to
short themes).

- Multi-clause compound asks in one sentence: `what type of accruals did he used to cover those 960 hours and
